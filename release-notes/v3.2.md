EDOS 3.2 loads binary files through a small loader in page 6, so a program may load over EDOS itself.

## Downloads
| File | What it is |
|---|---|
| `EDOS.COM` | the program (6,746 bytes); binary load from any DOS |
| `EDOS.FNT` | EDOS's character set (1,024 bytes); put it next to `EDOS.COM` on D1 |
| `EDOS.ATR` | bootable SpartaDOS 3.2 disk with EDOS.COM, EDOS.FNT, the MAC/65 sources (`LOAD #D:EDOS.M65`, then `ASM ,,#D:EDOS.COM`) and utilities |
| `EDOSTEST.ATR` | bootable test disk: EDOS.COM, EDOS.FNT, test files and `TESTPLAN.TXT` (35 manual checks) |

## Load Binary
- **Programs built for EDOS's own memory load.** Before, Load Binary read each segment with code inside EDOS ($1E00-$3FFF), so a program built for $2000 or $3000 overwrote the loader halfway and crashed. Now EDOS copies a 253-byte loader to page 6 ($0600-$06FF), and that loader reads the file, as DOS 2's own loader does with DUP.SYS.
- **The question comes first.** **Run Program [Y/N]?** is now asked before loading, because EDOS may not exist afterwards.
- **When a program loads over EDOS**, EDOS hands RESET back to DOS and selects the ROM font before that part is loaded. The program then runs if you said so; after it, or if you didn't, you are in DOS. Start EDOS again from there.
- **When EDOS is untouched**, you come back to the menu as before, and errors show as before.
- **Page 6 is the one place a program cannot load.** Loading stops before anything is written there, with "Program loads over $0600-$06FF".
- **A program's bytes at $3E00-$3EFF stay intact.** Segment headers used to be read into EDOS's buffer there, overwriting them.
- The file is read on IOCB #1, as DOS 2 does.

## Testing
Built and tested by GitHub Actions: 21 routine tests, 64 command tests, 6 source and tokenizer tests and 7 disk tests. The new tests cover:
- a program covering $2000-$40FF loads whole and runs, with RESET back to DOS and the ROM font;
- the same without running exits to DOS;
- a program in page 6 is refused;
- INIT code inside EDOS's memory runs.

The other 30 command scenarios are identical to 3.1. The 4 Load Binary scenarios load the same bytes, with the question asked first. The real MAC/65 1.01 assembles the sources with 0 errors.

Please check on the real Atari: `TESTPLAN.TXT` items 6-11, and the new 34 (`OVER.COM`, loads over EDOS) and 35 (`P6.COM`, page 6).
