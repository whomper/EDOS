EDOS 3.0 is 1,479 bytes (18.5%) smaller than 2.9 and fixes six bugs you can see on screen.

## Downloads
| File | What it is |
|---|---|
| `EDOS.COM` | the program (6,495 bytes, was 7,974); binary load from any DOS |
| `EDOS.FNT` | EDOS's character set (1,024 bytes); put it next to `EDOS.COM` on D1 |
| `EDOS.ATR` | bootable SpartaDOS 3.2 disk with EDOS.COM, EDOS.FNT, the MAC/65 sources (`LOAD #D:EDOS.M65`) and utilities |
| `EDOSTEST.ATR` | bootable test disk: EDOS.COM, EDOS.FNT, test files and `TESTPLAN.TXT` (33 manual checks) |

## Fixes
- **Analyze Sector** showed an inverse **FILES ON DISK** bar where "Sector: nnnn" belongs (the line ran on past its end into other texts).
- **Addresses with 3 digits** were read wrong: "600" became $0060, so Go To Address could jump into zero page; Save Binary, View File and Memory Status used the wrong address. One to four hex digits now work.
- **Error messages** had a stray character between the number and the text (`* Error 170#File not found`).
- **Memory Status** showed only a few bytes after Byte Compare on small files.
- **View File** showed the last block again when a file's length is a multiple of 128.
- Message 164 now reads "File number mismatch".

## Changes
- Each command's title bar is its menu label in inverse capitals ("GOTO ADDRESS" is now "GO TO ADDRESS").
- No text for error codes EDOS cannot cause (134, 141, 145, 166, 171); the number is still shown.
- Smaller code throughout: shared routines for printing, copying, filling, hex output, input and confirmations; tables instead of repeated code; variables moved out of the file and into free zero page. EDOS.COM is now one segment plus the run address.

## Testing
Built and tested by GitHub Actions: 20 routine tests, 60 command tests (every menu command on an emulated 6502 with a simulated DOS and drive), 4 source and tokenizer tests, 7 disk tests. Each change was compared with the previous build: screens, files and every CIO and SIO call match, apart from the fixes above.

Not yet verified on real hardware; please run `TESTPLAN.TXT`, especially Copy Files, Duplicate Disk and Initialize Disk. Known question: Initialize Disk sends the drive configuration (PERCOM) block as 11 bytes instead of 12, as earlier versions did; this may matter on drives that use it.
