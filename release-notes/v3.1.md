EDOS 3.1 loads the fast SIO code of drives whose code is longer than 256 bytes again, so Duplicate Disk copies at the drive's high speed.

## Downloads
| File | What it is |
|---|---|
| `EDOS.COM` | the program (6,493 bytes); binary load from any DOS |
| `EDOS.FNT` | EDOS's character set (1,024 bytes); put it next to `EDOS.COM` on D1 |
| `EDOS.ATR` | bootable SpartaDOS 3.2 disk with EDOS.COM, EDOS.FNT, the MAC/65 sources (`LOAD #D:EDOS.M65`, then `ASM ,,#D:EDOS.COM`) and utilities |
| `EDOSTEST.ATR` | bootable test disk: EDOS.COM, EDOS.FNT, test files and `TESTPLAN.TXT` (33 manual checks) |

## Fix
- **Fast disk copies.** Since 2.8 the drive's fast SIO code had a single 256-byte page at $3F00, and EDOS skipped any longer code, so Duplicate Disk ran at normal speed even on drives showing **HIGH**. The code now has its own 1,088 bytes at $3900-$3D3F, below the extended memory window.

## Also since 3.0
- The sources assemble in MAC/65 on SpartaDOS: `EDOS.M65` is now a short list of includes, and the program body is in `EDOSMAIN.M65`.

## Testing
Built and tested by GitHub Actions: 20 routine tests, 60 command tests, 6 source and tokenizer tests and 7 disk tests. The new routine tests load drive code of 257, 512 and 1,088 bytes and skip longer code. The 34 command scenarios are identical to 3.0 apart from the version in the title bar.

Please check on the real Atari: `TESTPLAN.TXT` item 23 (Duplicate Disk) on a drive showing **HIGH** should now copy at its high speed.
