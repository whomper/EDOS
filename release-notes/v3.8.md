EDOS 3.8 compares files 4K at a time and brings the test plan for the round on real 1050 drives.

## Downloads
| File | What it is |
|---|---|
| `EDOS.COM` | the program (7,305 bytes); binary load from any DOS |
| `AERA.FNT` | the AERA family's character set (1,024 bytes); put it next to `EDOS.COM` |
| `EDOS.ATR` | bootable SpartaDOS 3.2 disk with EDOS.COM, AERA.FNT, the MAC/65 sources (`LOAD #D:EDOS.M65`, then `ASM ,,#D:EDOS.COM`) and utilities |
| `EDOSTEST.ATR` | bootable test disk: EDOS.COM, AERA.FNT, test files and `TESTPLAN.TXT` (52 manual checks) |

## Changed
- **Byte Compare reads 4K of each file at a time**, instead of 255 bytes. With both files on one drive, the drive moves between them sixteen times less often. The answer is the same as before: the files are the same when they have the same length and the same bytes.
- Byte Compare now uses $4000-$4FFF and $6000-$6FFF (was $4000-$50FF), still inside the memory EDOS already needs.
- `TESTPLAN.TXT` has six new checks (47-52) for the round on the real 1050s: Byte Compare on one drive, the look of the screen, CAPS at a prompt, HIGH on the status line, Initialize Disk in each density, and a double-density disk.
- The README shows EDOS's icon and the 3.8 menu.

## Testing
Built and tested by GitHub Actions: 21 routine tests, 90 command tests (three new: Byte Compare at the 4K edges, a byte changed in any page of a block, and 4K reads), 6 source tests, 4 disk tests and xl's own. `difftest.py` against 3.7: only Byte Compare's reads differ.

In atari800, with its own OS ROM:
- EDOS 3.8 starts from `EDOS.ATR`;
- the real MAC/65 1.01 assembles the disk's sources with 0 errors to the same bytes as `EDOS.COM`.

Please check on the real Atari: `TESTPLAN.TXT` items 47-52, plus 32-33 and 42-46 if you haven't yet.
