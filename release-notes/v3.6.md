EDOS 3.6 loads its font with the AERA family's shared code. It works as before: AERA.FNT just below the screen, read once and selected again after RESET.

## Downloads
| File | What it is |
|---|---|
| `EDOS.COM` | the program (7,305 bytes); binary load from any DOS |
| `AERA.FNT` | the AERA family's character set (1,024 bytes); put it next to `EDOS.COM` |
| `EDOS.ATR` | bootable SpartaDOS 3.2 disk with EDOS.COM, AERA.FNT, the MAC/65 sources (`LOAD #D:EDOS.M65`, then `ASM ,,#D:EDOS.COM`) and utilities |
| `EDOSTEST.ATR` | bootable test disk: EDOS.COM, AERA.FNT, test files and `TESTPLAN.TXT` (46 manual checks) |

## Changed
- **The font is loaded by the family's shared code** (AERA-Atari's `xl/src/AXFONT.M65`), which every AERA 8-bit program now uses. It began as EDOS's own LDFONT, so it does the same:
  - `D:AERA.FNT` goes into the 1K just below the screen, read once and selected again after RESET;
  - without the file, or without room above $8000, EDOS keeps the Atari's font;
  - the Atari's font comes back before EDOS hands over to DOS or a program.
- **When there is no AERA.FNT,** EDOS now also selects the Atari's font itself, instead of leaving whatever was selected.
- **Load Binary protects the font's memory only when AERA.FNT is loaded.** With the Atari's font, a program may load at those addresses and EDOS stays.
- `AERA.FNT` on the disks and in the release is now the family's own file, the same bytes as before.

## Testing
Built and tested by GitHub Actions: 21 routine tests, 87 command tests (one new: Load Binary over the font's memory, with and without AERA.FNT), 6 source tests, 4 disk tests and xl's own.

In atari800, with its own OS ROM:
- EDOS 3.6 starts from `EDOS.ATR` with AERA.FNT;
- the real MAC/65 1.01 assembles the disk's sources with 0 errors to the same bytes as `EDOS.COM`.

Please check on the real Atari: `TESTPLAN.TXT` items 32-33 (the font), and 42-46 from 3.5 if you haven't yet.
